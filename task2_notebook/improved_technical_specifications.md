# Улучшенные технические спецификации для модели персонализированных рекомендаций

## 1. Методы предобработки данных (импутация, обработка отрицательных значений)

### Анализ альтернативных подходов

#### Методы импутации:
1. **Мода/медиана (используется в текущей реализации)**:
   - Преимущества: Простота реализации, быстродействие
   - Недостатки: Может вводить смещение, не учитывает корреляции между признаками

2. **KNN-импутация**:
   - Преимущества: Учитывает корреляции между признаками, более точная
   - Недостатки: Высокая вычислительная сложность, требует выбора параметров

3. **Импутация с использованием машинного обучения (например, IterativeImputer)**:
   - Преимущества: Учитывает сложные зависимости между признаками
   - Недостатки: Высокая сложность, риск переобучения

4. **Множественная импутация**:
   - Преимущества: Учитывает неопределенность в пропущенных значениях
   - Недостатки: Сложность реализации, увеличение размерности данных

#### Обработка отрицательных значений:
1. **Удаление записей (используется в текущей реализации)**:
   - Преимущества: Простота, гарантия отсутствия артефактов
   - Недостатки: Потеря данных, возможное смещение

2. **Замена на NaN с последующей импутацией**:
   - Преимущества: Сохранение количества записей
   - Недостатки: Введение потенциально некорректных значений

3. **Анализ причин отрицательных значений**:
   - Преимущества: Понимание источника проблемы, корректная обработка
   - Недостатки: Требует дополнительного анализа

### Обоснование выбранного решения

Для импутации категориальных признаков (region, socdem_cluster) сохраняем использование моды, так как:
- Эти признаки имеют низкую кардинальность
- Статистические методы могут не учитывать доменную специфику
- Мода обеспечивает стабильность и интерпретируемость

Для импутации числовых признаков (price) используем медиану, так как:
- Медиана более устойчива к выбросам, чем среднее значение
- Простота реализации и интерпретации
- Подходит для распределений с тяжелыми хвостами

Для обработки отрицательных значений цены сохраняем удаление записей, так как:
- Отрицательные цены в контексте маркетплейса не имеют бизнес-смысла
- Удаление небольшого количества записей не критично для обобщающей способности модели
- Это наиболее консервативный подход, не вводящий потенциально некорректных значений

### Потенциальное влияние на результаты модели

- Использование простых методов импутации может привести к небольшому снижению точности модели (1-3%) по сравнению с более сложными методами
- Удаление отрицательных значений может улучшить стабильность модели за счет удаления артефактов
- При увеличении доли пропущенных значений (более 10%) рекомендуется рассмотреть более сложные методы импутации

## 2. Выбор коэффициентов в экспоненциальных функциях (например, 0.1 для свежести товаров)

### Анализ альтернативных подходов

1. **Фиксированное значение (используется в текущей реализации, λ=0.1)**:
   - Преимущества: Простота, интерпретируемость
   - Недостатки: Не оптимизировано под данные, может быть субоптимальным

2. **Оптимизация через кросс-валидацию**:
   - Преимущества: Оптимальное значение для конкретной задачи
   - Недостатки: Дополнительные вычисления, риск переобучения

3. **Адаптивные коэффициенты**:
   - Преимущества: Учет динамики данных
   - Недостатки: Сложность реализации, потенциальная нестабильность

4. **Множественные временные признаки**:
   - Преимущества: Более полное представление временной динамики
   - Недостатки: Увеличение размерности, риск мультиколлинеарности

### Обоснование выбранного решения

Сохраняем использование экспоненциальной функции с коэффициентом 0.1, но с уточнениями:

1. **Теоретическое обоснование**: λ=0.1 означает, что вес события снижается в e раз (~2.7 раза) за 10 дней, что соответствует разумному временном окну релевантности

2. **Практическое обоснование**: 
   - Значение 0.1 обеспечивает умеренное затухание, позволяя учитывать как свежие, так и более старые события
   - Не слишком агрессивное затухание (λ=1.0), которое бы игнорировало историю пользователя
   - Не слишком медленное затухание (λ=0.01), которое бы делало все события равноценными

3. **Альтернативный подход**: Рассмотрение нескольких значений (0.05, 0.1, 0.2) через кросс-валидацию для определения оптимального значения

### Потенциальное влияние на результаты модели

- Слишком высокое значение λ может привести к игнорированию полезной исторической информации (снижение recall на 5-10%)
- Слишком низкое значение λ может привести к шуму от устаревших предпочтений (снижение precision на 3-7%)
- Оптимизация коэффициента может улучшить MAE на 2-5% по сравнению с фиксированным значением

## 3. Методы масштабирования (StandardScaler, MinMaxScaler)

### Анализ альтернативных подходов

1. **StandardScaler (используется в текущей реализации)**:
   - Преимущества: Центрирование данных, устойчивость к выбросам
   - Недостатки: Предположение о нормальности распределения

2. **MinMaxScaler**:
   - Преимущества: Приведение к фиксированному диапазону [0,1]
   - Недостатки: Чувствительность к выбросам

3. **RobustScaler**:
   - Преимущества: Устойчивость к выбросам
   - Недостатки: Меньшая интерпретируемость

4. **Отсутствие масштабирования**:
   - Преимущества: Сохранение исходных единиц измерения
   - Недостатки: Проблемы с сходимостью, доминирование признаков с большими значениями

### Обоснование выбранного решения

Рекомендуем использовать гибридный подход:

1. **Для признаков с нормальным распределением (total_views_log, total_events_log)**: StandardScaler
   - Обоснование: Логарифмические преобразования приближают распределения к нормальному виду
   - Преимущества: Оптимальное масштабирование для линейных моделей

2. **Для признаков с ограниченным диапазоном (item_price_log)**: MinMaxScaler
   - Обоснование: Логарифмированная цена имеет ограниченный диапазон
   - Преимущества: Приведение к стандартному диапазону [0,1]

3. **Для временных признаков (days_since_last_event)**: RobustScaler
   - Обоснование: Возможное наличие выбросов в временных данных
   - Преимущества: Устойчивость к экстремальным значениям

### Потенциальное влияние на результаты модели

- Неправильный выбор метода масштабирования может ухудшить MAE на 5-15%
- StandardScaler может быть неоптимальным для признаков с сильными выбросами
- MinMaxScaler может быть чувствителен к выбросам в ценах
- RobustScaler может улучшить стабильность модели на 2-4% при наличии выбросов

## 4. Выбор признаков для моделирования

### Анализ альтернативных подходов

1. **Ручной отбор (используется в текущей реализации)**:
   - Преимущества: Доменная экспертиза, интерпретируемость
   - Недостатки: Субъективность, возможное упущение важных признаков

2. **Статистические методы (корреляционный анализ)**:
   - Преимущества: Объективность, автоматизация
   - Недостатки: Не учитывает нелинейные зависимости

3. **Методы оценки важности признаков (feature importance)**:
   - Преимущества: Учет взаимодействий признаков
   - Недостатки: Зависимость от конкретной модели

4. **Рекурсивное устранение признаков (RFE)**:
   - Преимущества: Оптимизация под конкретную модель
   - Недостатки: Высокая вычислительная сложность

### Обоснование выбранного решения

Рекомендуем комбинированный подход:

1. **Базовый набор признаков** на основе доменной экспертизы:
   - total_events, total_views (активность пользователя)
   - price, item_price_log (характеристики товара)
   - days_since_last_event, item_recency_score (временные признаки)

2. **Дополнительные признаки** на основе корреляционного анализа:
   - Отбор признаков с корреляцией > 0.1 с целевой переменной
   - Удаление сильно коррелирующих признаков (|r| > 0.8) для уменьшения мультиколлинеарности

3. **Инженерия признаков**:
   - Создание полиномиальных признаков для ключевых переменных
   - Взаимодействия между категориальными и числовыми признаками

### Потенциальное влияние на результаты модели

- Недостаточный набор признаков может ухудшить MAE на 10-20%
- Избыточный набор признаков может привести к переобучению (ухудшение на тестовой выборке)
- Правильный отбор может улучшить интерпретируемость без потери качества
- Удаление мультиколлинеарности может улучшить стабильность коэффициентов на 15-25%

## 5. Выбор моделей для сравнения (Linear Regression, Decision Tree Regressor, Random Forest Regressor)

### Анализ альтернативных подходов

1. **Линейные модели (Linear Regression - используется)**:
   - Преимущества: Интерпретируемость, простота, быстродействие
   - Недостатки: Ограничения в моделировании нелинейностей

2. **Деревья решений (Decision Tree - используется)**:
   - Преимущества: Учет нелинейностей, интерпретируемость
   - Недостатки: Склонность к переобучению

3. **Ансамблевые методы (Random Forest - используется)**:
   - Преимущества: Высокая точность, устойчивость к переобучению
   - Недостатки: Сниженная интерпретируемость

4. **Градиентный бустинг (XGBoost, LightGBM)**:
   - Преимущества: Высокая точность, эффективность
   - Недостатки: Сложность настройки, риск переобучения

5. **Регрессия с регуляризацией (Ridge, Lasso)**:
   - Преимущества: Устойчивость к мультиколлинеарности
   - Недостатки: Требует настройки гиперпараметров

### Обоснование выбранного решения

Сохраняем выбранные модели, но с расширением:

1. **Linear Regression** как baseline:
   - Обоснование: Простота интерпретации коэффициентов
   - Использование: Базовая линия для сравнения

2. **Decision Tree Regressor**:
   - Обоснование: Понимание нелинейных зависимостей
   - Уточнение: Ограничение глубины для предотвращения переобучения

3. **Random Forest Regressor**:
   - Обоснование: Баланс точности и устойчивости
   - Уточнение: Настройка количества деревьев и глубины

4. **Дополнительные модели**:
   - **Ridge Regression**: Для сравнения с линейной регрессией при наличии мультиколлинеарности
   - **XGBoost Regressor**: Для проверки возможности улучшения качества

### Потенциальное влияние на результаты модели

- Linear Regression может уступать нелинейным моделям на 10-15% по MAE
- Decision Tree может показывать высокую дисперсию результатов
- Random Forest обычно показывает лучшие результаты, чем отдельные модели
- Добавление XGBoost может улучшить MAE на 3-8% по сравнению с Random Forest
- Ridge Regression может улучшить стабильность линейной модели на 2-5%
