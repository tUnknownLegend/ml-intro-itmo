1. **Добавление раздела с описанием данных**: В notebook-файле данные загружаются из нескольких источников (brands.pq, users.pq, items.pq, события из marketplace/events). Однако, не объяснено, почему это важно для конкретной задачи. Необходимо расширить обоснование, объяснив, как MAE связана с бизнес-целями (например, минимизация разочарования пользователей из-за нерелевантных рекомендаций).

4. **Добавление раздела с практическим применением**: В notebook-файле не описано, как результаты модели будут использоваться в реальной системе рекомендаций. Необходимо добавить описание практического применения, включая, как модель будет интегрирована в существующую систему, как часто она будет переобучаться, и как будут обрабатываться новые пользователи и товары.

5. **Добавление раздела с ограничениями исследования**: В notebook-файле не указаны факторы, которые не были учтены (например, сезонность, маркетинговые кампании), и допущения, которые были сделаны (например, что все события просмотра равнозначны). 1. **Обоснование методов предобработки данных**: В notebook-файле для заполнения пропущенных значений используются простые методы (мода, медиана). Это сделано для простоты реализации и быстродействия. Более сложные методы (например, KNN-импутация) могли бы дать лучшие результаты, но требуют больше вычислительных ресурсов и времени. Альтернативные значения (например, 0.01 или 1.0) могли бы сделать функцию более или менее чувствительной к свежести данных. Для оптимизации коэффициента можно было бы использовать перекрестную проверку.

Выбор этих моделей обусловлен их разной сложностью и интерпретируемостью. Linear Regression - простая и интерпретируемая модель. Decision Tree Regressor - более сложная модель, способная улавливать нелинейные зависимости. Random Forest Regressor - ансамблевая модель, которая обычно дает высокую точность. ## Нарушения PEP8 и проблемы с кодом

### Основные нарушения стандартов кодирования

1. **Длинные строки**: Некоторые строки превышают рекомендованные 79/88 символов, особенно в комментариях и print-выражениях.

2. **Несоблюдение консистентности в отступах**: Неконсистентное использование пустых строк между блоками кода.

3. **Отсутствие docstring**: Ни одна из определенных функций не имеет документации в формате docstring.

4. **Неочевидные названия переменных**: Некоторые переменные имеют неочевидные названия (например, e2, mode_region[0]).

5. **Дублирование кода**: Повторяющиеся блоки для обработки отсутствующих значений в разных датафреймах.

6. **Использование inplace=True**: Использование параметра inplace=True в методах pandas, что может привести к неочевидным изменениям данных.

7. **Отсутствие типизации**: Отсутствие type hints для функций.

### Предложения по улучшению кода

1. **Разбить длинные строки**: Разделить длинные строки на несколько строк для улучшения читаемости.

2. **Соблюдать консистентность в отступах**: Использовать консистентное количество пустых строк между блоками кода.

3. **Добавить docstring**: Добавить документацию в формате docstring ко всем функциям с описанием параметров и возвращаемых значений.

4. **Использовать понятные названия переменных**: Заменить неочевидные названия переменных на более понятные.

5. **Устранить дублирование кода**: Вынести повторяющийся код в отдельные функции.

6. **Избегать inplace=True**: Избегать использования параметра inplace=True, создавая новые объекты вместо изменения существующих.

7. **Добавить типизацию**: Добавить type hints для функций для улучшения читаемости и поддержки IDE.

8. **Добавить логирование**: Заменить print-выражения на логирование для более гибкого управления выводом.

### Обоснование решений

1. **Длинные строки**: В notebook-файле есть длинные строки, особенно в print-выражениях. Это сделано для удобства отладки и отображения информации. Однако для улучшения читаемости кода рекомендуется разбить длинные строки на несколько строк.

2. **Несоблюдение консистентности в отступах**: В notebook-файле не всегда соблюдается консистентность в отступах. Это может затруднить чтение кода. Рекомендуется использовать автоматическое форматирование кода (например, с помощью black) для обеспечения консистентности.

3. **Отсутствие docstring**: В notebook-файле функции не имеют docstring. Это затрудняет понимание назначения функций и их параметров. Рекомендуется добавить docstring ко всем функциям.

4. **Неочевидные названия переменных**: В notebook-файле используются неочевидные названия переменных (например, e2). Это затрудняет понимание кода. Рекомендуется использовать более понятные названия переменных.

5. **Дублирование кода**: В notebook-файле есть дублирование кода для обработки отсутствующих значений. Это увеличивает размер кода и усложняет его поддержку. Рекомендуется вынести повторяющийся код в отдельные функции.

6. **Использование inplace=True**: В notebook-файле используется параметр inplace=True. Это может привести к неочевидным изменениям данных. Рекомендуется избегать использования inplace=True, создавая новые объекты вместо изменения существующих.

7. **Отсутствие типизации**: В notebook-файле отсутствует типизация. Это затрудняет понимание кода и может привести к ошибкам. Рекомендуется добавить type hints для функций.
